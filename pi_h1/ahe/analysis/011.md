## Likely causes
- **Proven:** missing expected shell utility `xxd` in the environment (**011:3**).  
- **Likely harness/process weakness:** lack of guardrails for preserving/restoring fixture state led to repeated ad hoc resets and erroneous comparisons (**011:34**, **011:39**–**011:45**, **011:68**–**011:75**).  
- **Likely model weakness (workflow discipline, not core coding):** brittle shell scripting/comparison hygiene under long-horizon testing, evidenced by path typos and invalid test commands (**011:19**, **011:28**, **011:67**).

## Generic harness fixes
- Provide a **stable reset mechanism** for benchmark fixtures (snapshot/restore command) so agents do not manually rebuild data files.
- Add **artifact-preservation middleware** to discourage deleting reference binaries/backups before final verification.
- Offer a **standard diff/compare utility wrapper** that records “before” and “after” outputs correctly and reduces shell mistakes.
- Include a **portable byte-inspection toolset** or documented fallback commands so missing utilities don’t derail analysis.

## Component choice
- **Primary:** **middleware** — state reset, snapshotting, and safe comparison orchestration would have prevented most observed workflow errors (**011:34**, **011:68**–**011:75**).
- **Secondary:** **tool description** — clearer availability/limitations for shell tools could reduce failed attempts like `xxd` (**011:3**).
- **Tertiary:** **skill** — reusable “verify against reference implementation” procedure for disciplined baseline handling.

## Regression risks
- Tightening cleanup rules could impede legitimate temp-file management if too strict.
- Snapshot/reset middleware may mask bugs that only appear with cumulative state unless explicitly configurable.
- Standardized compare wrappers must avoid encoding assumptions, since these tasks use fixed-width raw file content.
