## Likely causes

- **Model capability limit:** difficulty maintaining binary-format invariants across many iterative edits; especially distinguishing file offsets, virtual addresses, and ELF field offsets. Root-cause claims supported by task **023**, steps **25/27/32/51/52**.
- **Prompt/strategy weakness:** the agent overcommitted early to a bespoke parser without verifying contract-relevant assumptions, then anchored on wrong interpretations and hardcoded them. Supported by steps **3**, **25**, **38**, **50**, **63**, **70**.
- **Not an infrastructure failure:** shell/tool availability was mostly adequate; missing `xxd`/`file` in steps **9** and **12** was minor and bypassed with `readelf`, `objdump`, `nm`, `strings` available in step **28**.

## Generic harness fixes

- Add a **binary-format parsing skill** or vetted library guidance for ELF/PE/Mach-O tasks, reducing reinvention of header parsing.
- Add middleware checks for **stdout purity** when the task requires machine-readable output; fail fast if non-JSON text is emitted (task **023**, steps **84–85**).
- Encourage an incremental harness policy: verify **single invariant checkpoints** (e.g., “parse `e_shoff` and section count, compare with `readelf`”) before writing full solutions.
- Add a generic reminder to distinguish **file offsets vs. virtual addresses vs. relocated runtime addresses** for binary tasks.

## Component choice
- **Primary:** **skill** (binary parsing / ELF handling)
- **Secondary:** **middleware** (output validation / stdout purity)
- **Tertiary:** **prompt** (insist on checkpointed verification before implementation)

## Regression risks

- Adding stronger output validation may break otherwise-acceptable verbose agents unless scoped to machine-readable tasks.
- Encouraging external-tool cross-checks could create overreliance on `readelf`-specific workflows if similar tools are unavailable elsewhere.
- A binary-parsing skill must avoid task-specific leakage; keep it format-generic.
