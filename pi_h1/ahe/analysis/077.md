## Likely causes
- **Success cause:** The repository contained straightforward, grep-detectable hardcoded credentials, and the harness exposed enough shell/file-edit tooling for the agent to inspect, patch, and verify them (**Steps 4–6, 19, 21, 25, 27–33**).
- **Minor failure cause (hypothesis):** The agent’s internal state tracking was somewhat brittle when evidence came from embedded diff strings rather than normal files, leading to premature claims about file locations (**Steps 14–17**).
- **Tooling limitation (proven):** Exact-string structured edits are fragile on escaped JSON blobs (**Step 23**), requiring fallback to raw text substitution (**Step 25**).

## Generic harness fixes
- Add a **secret-sanitization skill** that distinguishes:
  - hardcoded live secrets,
  - environment-variable references,
  - historical/diff/serialized text containing secrets.
- Improve middleware/tooling with a **search result provenance helper** so agent summaries cite the actual source file/content type before claiming a file exists.
- Provide a **robust replace primitive** for escaped/serialized content to reduce failures like **Step 23**.

## Primary component choice
- **Skill**: strongest fit, because the rollout succeeded but relied on ad hoc search/replace logic and weak provenance handling.
- Secondary: **tool implementation** (structured edit on escaped JSON was brittle).
