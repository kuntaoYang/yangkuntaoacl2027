- **Model capability limit under long-horizon dependency handling**: once partial success was reached, it failed to distinguish “object compilation works” from “tool is fully functional as requested” at **157–175**.

## Generic harness fixes

- Add a **postcondition checker** for build tasks: verify the exact requested invocation path and both compile-only and compile+link behavior from that path, without ad hoc flags. This would have caught the false positive seen at **155, 158, 168, 175**.
- Provide a **stable environment manifest / prerequisite probe skill** so the agent quickly knows which common tools are missing, instead of discovering piecemeal.
- Add **workspace normalization middleware**: canonicalize extracted source root, detect nested top-level dirs, and summarize file counts/important files after extraction to prevent path confusion.

## Primary component choice

- **Middleware** (primary): state/path normalization and postcondition verification would likely have prevented the miss.
- Secondary: **skill** (dependency probing / artifact validation).

## Regression risks

- Tightening postchecks may reduce false positives but increase runtime on successful builds.
- Adding automatic normalization around extraction could mask genuine permission/archive issues if logs are oversimplified.
- If the harness encourages “patch to make it build,” models may over-edit upstream sources; this rollout already patched source at **152**, so validation should distinguish build success from unsupported source modifications.
