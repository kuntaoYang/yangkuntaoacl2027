## Generic harness fixes

- Provide a **library-version-specific tool hint** for common packages with import-name/API mismatches (e.g., PyStan 3 uses `stan`, not `pystan`).
- Add a **post-install verification skill**: import package, print version, inspect canonical entry points before writing code.
- Add a **completion check middleware**: after execution, explicitly verify required output files exist and are nonempty; if observation is empty, mark run as incomplete and re-query.
- Prefer a **dependency preflight** for build-heavy ML tasks: compiler availability, Python package importability, and common optional deps used by chosen APIs.

## Component choice

## Regression risks

- More prescriptive tool hints may overfit to one package version and mislead on other tasks.
- Automatic dependency preflights may increase latency/cost.
- Aggressive completion verification could cause duplicate long-running executions if middleware mishandles delayed output.
