## Generic harness fixes
- Add a **preflight schema inspection/canonicalization checklist** before code generation or execution for multi-source tasks.
- Encourage or enforce **artifact-level validation** (not just execution success): check output row counts, schema, and report consistency before declaring completion.
- Add a reusable **structured merge/conflict-report skill** for common ETL tasks to reduce ad hoc rewrites after partial success.

## Component choice
Primary: **skill**  
Secondary: **prompt/tool description**

Reason: the failure modes center on reusable ETL behaviors—schema normalization, key handling, and conflict reporting—not tool malfunction.

## Regression risks
- A stronger canonicalization/validation skill may increase verbosity or extra verification steps on simple tasks.
- Over-regularizing merge behavior could create brittleness when tasks legitimately require preserving source-specific fields or different conflict semantics.
- Prompting for more preflight checks may slow successful runs if not scoped to heterogeneous-source tasks.
