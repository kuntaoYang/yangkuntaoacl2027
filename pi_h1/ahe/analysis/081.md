## Likely causes
- **Primary root cause (proven mismatch):** failure to track and satisfy the exact filesystem requirement from step **1**; the agent optimized for a standard `/usr/local` install instead.
- **Secondary hypothesis:** prompt/tooling did not emphasize validating all explicit user constraints before declaring completion.
- **Not infrastructure:** step **2** tar permission/mode warnings were recoverable; extraction still succeeded by step **3**.

## Generic harness fixes
- Add a **constraint-checklist middleware** that extracts explicit requirements (here: location, source path, PATH availability) and requires end-of-task verification against each.
- Add a **completion gate**: before final answer, verify target paths exist exactly as requested, not just functionally equivalent substitutes.
- Add a **stop-when-done heuristic** to reduce post-success noisy probes and failed experiments.
- Improve command-result reflection so the agent distinguishes “build/runtime instrumentation confirmed” from unrelated runtime SQL experiments.

## Component choice
- **Primary:** middleware  
- **Secondary:** prompt / memory

## Regression risks
- Over-enforcing literal paths may reduce flexibility when equivalent installs are acceptable; gate should distinguish explicit path requirements from defaults.
- Stronger completion gating may increase runtime/tool calls if not paired with concise verification templates.
- Stop-early heuristics could suppress useful validation unless the checklist explicitly preserves required final checks.
