## Likely causes
- **Proven infrastructure/tooling gaps:** missing standard diagnostics/process tools (`ps`, `pkill`, `fuser`, `ss`) materially impeded recovery (`037` steps **8**, **19–20**, **46**, **85**).
- **Proven middleware/harness weakness:** background jobs and long-lived services were hard to manage/inspect; logs were inconsistent or stale (`037` steps **7**, **12**, **24–30**, **88**, **99**).
- **Model capability limit (secondary):** the agent could debug substantive issues, but lost coherence under long-horizon state management and repeated self-modification, causing regressions (`037` steps **64–74**, **93–99**, **116**).

## Generic harness fixes
- Provide a **service supervisor primitive** (start/stop/status/logs/port ownership) instead of relying on shell backgrounding.
- Expose a **stable process/port introspection tool** in middleware.
- Add a harness pattern for **write-once, validate-before-editing** service files to avoid iterative regressions.
- Encourage checkpointed verification: after each fix, assert **single listener + required port + functional endpoint** before further edits.
