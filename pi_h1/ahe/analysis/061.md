- **Prompt / middleware weakness:** no persistent reminder that “single-file `/app/polyglot/main.rs`” remained mandatory, even after alternative ideas emerged ([061, steps 59, 64]).
- **Weak stopping criteria:** the agent kept iterating after repeated compile failures without a strategy shift beyond more ad hoc syntax experiments ([061, steps 11→55]).

## Generic harness fixes
- Add a **requirements lock** in middleware: track immutable task constraints (single file, exact path, exact invocation forms) and warn/block when the agent proposes alternatives.
- Require **end-to-end self-checks** before finalization: confirm both exact user commands succeed on the exact target file.
- Add a **claim validator**: discourage unsupported impossibility claims unless backed by benchmark policy or formal proof.
- Encourage **strategy reset after repeated similar failures** (e.g., after N compile-error loops, summarize constraints and search space instead of continuing random rewrites).

## Primary component choice
- **Middleware** (best fit): enforce invariant task constraints and exact-command validation.
- Secondary: **Prompt** (for anti-drift and anti-overclaiming), **Skill** (for structured polyglot/search problem-solving).

## Regression risks
- Hard constraint enforcement may prematurely stop creative exploration on legitimately tricky synthesis tasks.
- Stricter final-command validation could increase token/tool usage.
- Anti-overclaiming rules may make the agent more cautious, potentially reducing useful high-confidence pruning in easier tasks.
