## Generic harness fixes
- Add a **success-gate/stop condition**: after endpoint checks pass and required services are up, discourage further destructive changes.
- Add a **deployment checklist skill** for common server tasks: bare-repo hook placement, SSH password-auth verification, and safe service reload vs restart.
- Prefer **structured verification prompts**: require proving clone/push/hook/HTTPS with the same access method expected by tests, not ad hoc alternatives.
- Add middleware warnings on risky commands after success (e.g., reinitializing repos, deleting service state).
