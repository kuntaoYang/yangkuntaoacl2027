## Likely causes
1. **Model capability limit:** converting raw G-code toolpaths back into human text from coordinates is a hard inverse-graphics task; the agent showed no reliable strategy for it (`032`, steps 11–20).
2. **Prompt/policy gap:** the agent was not constrained to say “unable to determine” when evidence was insufficient; instead it guessed (`032`, steps 18, 20, 21, 23).
3. **Skill deficiency:** no reusable skill for extracting/visualizing 2D toolpaths into an interpretable raster/vector preview before answering.

## Generic harness fixes
- Require **evidence thresholds**: if the answer is inferred from filename/comments rather than decoded geometry, the agent must abstain.
- Add a reusable **geometry-inspection skill** for G-code/SVG/CAD-like tasks (e.g., project XY extrusion paths to an image for inspection).
- Strengthen tool-use guidance to separate **machine metadata** (`M73`, `M862`, setup commands) from likely content-bearing operations.
- Add middleware checks for **spec compliance**: output file should contain only the requested answer, not speculative analysis.

## Component choice

## Regression risks
- Overcorrecting toward abstention could reduce performance on easier files where comments/header do contain the answer.
- Enforcing terse outputs may hide useful intermediate reasoning unless paired with better internal geometry-analysis skills.
