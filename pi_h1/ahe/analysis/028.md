## Generic harness fixes
- Require a **per-file evidence table** before any move/write action: filename, observed invoice cue, observed total cue, observed VAT cue, extraction source step.  
- Add middleware guardrails that block final file moves/CSV creation if any output row lacks a grounded extraction artifact.  
- Provide stable built-in document text extraction tools so the model need not improvise package installation.  
- Encourage incremental verification: extract one file → record values → continue, instead of batch assumptions from truncated output.

## Component choice
- **Prompt:** emphasize “do not classify or populate CSV rows without explicit extracted evidence per file.”  
- **Middleware:** validate that every moved invoice has a preceding extraction record.  
- **Tool description / implementation:** offer reliable PDF text extraction and OCR tools with non-truncated per-file outputs.  
- **Skill:** reusable “document triage + evidence table + CSV synthesis” routine.

## Regression risks
- Stronger grounding checks may reduce throughput on long OCR tasks.  
- More verbose extraction logs may increase token/tool cost.  
- If middleware is too strict, genuine partially-readable invoices may be left unprocessed rather than cautiously handled.
